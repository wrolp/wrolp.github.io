User manual/Chapter 6

What is supported

Local port-forwarding rules are stored per connection. They can be added, edited, deleted, started and stopped from the sidebar. Because tunnels are carried by the SSH session itself, they reuse the same russh channel as the terminal.

State synchronisation

When tunnel state changes, the backend emits tunnel-changed so the UI reflects the actual state rather than a local guess.

Not confirmed. The source material describes local forwarding only. It does not document remote forwarding (-R), dynamic SOCKS forwarding (-D), a bind-address field, a preferred local port, or whether rules auto-start when a connection opens. Fields and defaults for the add/edit dialog are also not documented.

Using a tunnel

The confirmed workflow is limited to what the README states: create a local forwarding rule for a connection, then start or stop it from the sidebar and confirm the state change propagated from the backend.

Operational note. A tunnel lives on the SSH session that owns it, so a tunnel stop can also follow from the session closing; the documented connection-closed status is the signal to watch in the tab.

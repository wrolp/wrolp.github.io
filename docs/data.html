What is stored

File or directoryContents
window.jsonWindow, recording and keepalive settings
connections.jsonConnections and workspaces, stored encrypted
wrolp.dbSQLite database: session index, command sets, snippets
recordings/NDJSON session recordings
vault.keyAES-256-GCM vault key, described as a machine-bound file
data_root.jsonRecords the chosen data directory; kept at the default location
Not confirmed. The actual default data directory path is not stated in the source material; only that data_root.json lives there and records the choice.

Relocating the data directory

Settings can point the data directory at any location. wrolp.db, recordings/, connections.json and the window configuration migrate together.

  • The choice is written to data_root.json at the default location and takes effect on the next start.
  • If the target is empty, the existing data is copied into it.
  • If the target is not empty, it is reused.
  • Existing data is never overwritten.
  • vault.key can optionally be migrated with the rest, which is what makes the whole directory portable.

Backup considerations

There is no dedicated backup command in the documentation; migration moves the same files that a backup would need to capture. A consistent copy should include wrolp.db, recordings/, connections.json, window.json and, if you want the AI keys to travel, vault.key.

Not confirmed. Whether a vault.key copied to another machine remains usable is not documented — it is only described as machine-bound. The documentation also does not describe online backup, cloud sync or a supported restore procedure, and does not state whether wrolp.db is encrypted.

Database maintenance

Settings show the current size of wrolp.db and the space that can be reclaimed, with a Compact now action that runs VACUUM.

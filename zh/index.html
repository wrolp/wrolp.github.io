Wrolp Terminal 是一个基于 Tauri 2 + React 19 + TypeScript 构建的桌面终端与服务器运维工具。 它把“连接服务器、传输文件、编辑文件、查看日志、管理容器、管理 K8s、管理 Git、向 AI 提问” 收进同一个应用窗口，替代原本需要在 SSH 客户端、SFTP 工具、编辑器、Docker 面板和 Git GUI 之间来回切换的工作流。

它与传统 SSH 客户端的核心差异：SSH 连接直接由 Rust 侧的纯 Rust 异步库 russh 实现 （不依赖外部 ssh 命令或 OpenSSH 二进制），因此终端、SFTP、隧道、Docker exec 和 kubectl exec 全部复用同一个会话通道。本地与远程文件浏览共用一套 RemoteFs 抽象，本地 shell 和远程主机 可以在同一个界面里并排使用。

连接与终端

由 xterm.js 渲染的多标签 SSH 终端，另有 Telnet、串口（COM）和本地 shell。SSH 基于 russh，而不是外部 OpenSSH 二进制。

文件与编辑

支持暂停与续传的 SFTP 浏览，按文件展示的传输队列，带 UTF-8/GBK 识别的 Monaco 编辑，以及十六进制或图片预览。

服务器运维

Docker 与 podman 主机、Kubernetes/Helm，以及由真实 git CLI 驱动的 Git 面板。Kubernetes 与 Git 面板会根据当前聚焦的终端选择主机。

AI 助手

Chat 与 Agent 两种模式，应用级与分栏级相互隔离的会话，以及只插入不执行的“发送到终端”步骤，方便执行前检查。

已知限制与缺失信息

  • 发布包仅提供 MSI：tauri.conf.json 中的打包目标为 ["msi"]，因此 Linux/macOS 用户必须从源码构建。
  • README 描述的是代码当前状态，而不是路线图（原文为 “not a roadmap”），仓库中也没有路线图或规划文档。
  • 没有 CONTRIBUTING.md：只有 issue 模板（缺陷报告与功能请求）和 pull request 模板；实际约定以 README 中的说明为准。
  • 没有 CI 配置：文件树中不存在 .github/workflows/，因此无法确认存在自动化构建/测试流水线。
  • 仓库规模较小、star 很少（4 个），也没有可参考的外部用户反馈。
